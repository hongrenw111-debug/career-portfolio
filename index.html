先理解失败，再设计恢复

不论做模型网关还是内容与评测管线，推进顺序保持一致：先识别故障根因，再划定不可重试或人工边界，最后留存可重复核验的证据。

  1. 分类

    网络波动、地区限制、配额耗尽与模型缺失是不同故障，不能共用一套盲目重试掩盖问题。

  2. 划界

    响应头或首个响应字节发出后不再自动重放；涉及账号安全或发布不可逆时由确定性闸门硬拦并留人确认。

  3. 定责

    共享网络与进程依赖只保留单一恢复所有者，避免多个守护逻辑并发重启放大故障面。

  4. 验证

    用离线确定性测试、真实语料回扫与脱敏日志校验代替口头汇报，不隐藏样本缺口。

交互演示：一次失败模型请求如何被安全分流

切换四种常见异常信号，观察 Provider Guard 如何判定根因并划定不可自动重放的边界。

  1. 发现信号 连接失败 请求尚未向下游输出
  2. 识别原因 出口节点异常 先识别根因，不做通用重试
  3. 确定责任 Provider Guard 只有一个恢复所有者
  4. 执行决策 切换健康节点 总尝试次数不超过 3 次
安全结果 在未输出响应头或响应字节前安全重放

节点故障属于可恢复网络边界；一旦响应头或首个响应字节已发往客户端，立即停止自动重放。
