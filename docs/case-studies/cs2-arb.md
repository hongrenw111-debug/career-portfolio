# Case Study 07 — cs2-arb：CS2 跨平台套利决策辅助工具

## 结论

当前完成的是**全离线可验证的决策辅助 CLI**：悠悠有品与 Steam 之间的价差扫描、费用与冷却期建模、持仓跟踪。25 个测试文件、258 个用例全绿（2026-10-22 实测，3.65 秒）。**不做自动交易**——Steam 订阅协议禁止 bot 自动化，这条边界写进了 ADR-0002。

## Constraint

- 套利判断不是价格相减。两端费用结构不同：悠悠卖出 0% 但提现 1%（最低 2 元），Steam 到手约为挂单价 ÷1.15 − 0.01。
- Steam 余额官方不可提现，社区变现价值约 7 折；饰品有 7 天交易冷却，期间不可卖。
- 任何一项算错，账面盈利就是假的。而行情数据源的稳定性直接决定这个工具是否成立。

## Decision

- **先证明数据源拿不稳，再决定不去爬它**。原计划自采悠悠有品私有接口，实测该接口需约 10 天过期的 Bearer token、AES 设备码，且有 TLS 指纹检测、数据中心 IP 风控（错误码 84104）与限频。作为行情层既不稳定也不安全，改走聚合 API（CSQAQ），Steam 侧用公开端点补充。
- **拒绝代理轮换**。Steam 侧自限 ≤15 req/min，并明确不换 IP——实测代理轮换会导致账号锁定。这是用真实代价换来的边界。
- **费用与冷却期可配置，不硬编码**（ADR-0003）。费率会变，冷却规则会变，写死在计算里就是定时炸弹。
- **只做决策辅助，不做执行**（ADR-0002）。Steam 订阅协议禁止 bot 自动化交易，工具的输出是「值不值得做」，不是「替你做」。

## Mechanism

```text
聚合行情 API / 录制快照
→ 两端费用与折价模型（可配置）
→ 7 天冷却期收益分布
→ 方向A（现金换余额）/ 方向B（余额换现金）双向扫描
→ 跨品种闭环与历史分位
→ CLI 输出 / 只读 Web
```

## Evidence

- 2026-10-22 实测 `npm test`：**25 个测试文件、258 个用例全部通过**，3.65 秒，全程离线。
- `fixtures/` 下录制行情快照，测试不触网，可复现。
- `docs/adr/` 三份决策记录：行情走聚合 API 而非自爬私有接口、只做决策辅助不做自动化、费用与冷却必须可配置。
- `CONTEXT.md` 维护领域词汇表（寄售 / 求购 / 挂刀 / 方向A / 方向B），把社区俚语与业务概念对齐，避免实现时各说各话。

## 当前边界

- 输出为决策辅助，不执行任何交易动作。
- 公开演示以离线快照为主；实时扫描需要数据源可达。
- 258 个测试覆盖的是**计算与边界**，不是盈利能力。测试绿不等于策略赚钱。

## 这个案例的面试价值

大部分候选人的项目讲「我实现了什么」。这个项目的核心是一次**否定性的技术判断**：探测清楚私有接口的风控成本后，主动放弃自爬方案。同时它展示了「该做的边界不越」——工具做到决策为止，执行不碰。这两点比多写几个功能更能说明工程成熟度。
