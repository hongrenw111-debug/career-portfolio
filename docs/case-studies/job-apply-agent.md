# Case Study 02 — Job Apply Agent 求职触达系统

## 结论

当前完成的是**本地运行的半自动求职 Agent**：三平台（BOSS直聘 / 猎聘 / 智联）搜索、JD 解构、定制简历与话术生成、对齐质检与投递记录全链路可用，107 项测试通过；真实投递前仍需真机校准平台选择器，不宣称已完成线上投递验证。

## Constraint

- 自动投递工具普遍用同一份简历群发，回复率低，且 LLM 直接生成简历极易编造经历——对求职者是诚信风险。
- 人工按岗定制一份简历需要一小时，覆盖不了批量岗位。
- 招聘平台存在反自动化风控：高频、匀速、失败后立刻重试的行为都会触发限制。

## Decision

- **取材红线**：定制简历的每个句子必须能在 `master_resume.md` 原文中找到出处；缺口保持缺口，对齐分不足或质检不过的职位标记 cannot-align，直接放弃投递。
- **分层（ADR-0003）**：LLM 行为层（解构 / 映射 / 定制 / 质检）与 Playwright 机械层（搜索 / 投递 / 记录）通过 JSON 作业文件解耦，LLM 故障不影响已排队的投递动作。
- **节奏护栏（ADR-0001）**：每轮投递上限、连续失败熔断暂停、投递间隔 ±20% 抖动、指数退避、验证码 / 风控信号秒级停机不硬闯。
- **自研而非 fork（ADR-0002）**：现成开源投递工具以"快速群发"为目标，与"可核查定制"目标冲突，故自建。

## Mechanism

```text
职位（搜索或手动）
→ JD 解构为需求清单（R1/R2…，硬性 / 加分 / 关键词）
→ 逐条证据映射（证据行逐字引用自主简历）
→ 定制简历 + ≤50 字话术（+ 日语岗自己PR）
→ 对齐质检（时间线 / 数字回指 + 关键词堆砌检测）
→ cannot-align 拦截 或 Playwright 投递（抖动节奏）
→ JSONL 投递记录 + 去重
```

## Evidence

- 2026-09-14 实测 `node --test`：107/107 通过，约 18 秒。
- 对齐校验器对编造时间线、编造数字与关键词堆砌三类违规逐条拦截，命中即标记 cannot-align。
- `docs/adr/` 四份决策记录覆盖节奏护栏、自研决策、行为层 / 机械层分层与简历事实源（ADR-0004：主简历为唯一事实源，日语仅入辅助材料）。
- 投递默认 dry-run 起步；真实投递前需真机校准选择器并小批次试水，当前如实标注为进行中。
