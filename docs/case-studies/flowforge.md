# Case Study 02 — FlowForge 开源 AI 导演调度工作台

## 结论

当前完成的是**公开开源、双系统 CI 全绿的 Agent 原生视频生成工作台**：通过 CDP 复用本地已登录的 Chrome 会话驱动 Google Flow，支持锚定帧画风锁定与尾帧接力接续，209 个单元测试在 Ubuntu + Windows 双系统回归通过。不宣称支持云端无头集群并发。

## Constraint

- 传统 AI 视频工具逐镜生成，镜头之间画风断裂，无法构成连贯叙事。
- 商业视频 API 按次计费，长镜头接力场景成本不可控。
- 浏览器端生成受画质压缩影响，直接截屏会损失分辨率并可能取到未完成的伪视频。

## Decision

- **零 API Key**：复用本地 Chrome 已登录的 Flow 会话，通过 CDP 驱动，不引入凭据管理面。
- **尾帧接力**：抽取前一镜第 8 秒末尾帧注入下一镜首帧，让模型在本镜内完成画风过渡，而不是靠后期调色硬拼。
- **画风锚定**：以原画首帧强制对齐，约束跨镜头的角色与色调漂移。
- **损坏熔断**：逐帧探测 `moov atom` 完整性与体积门禁（<100KB 判为伪视频，自动剔除并重试），避免把半成品剪进成片。
- **可复现优先**：脚本声明式描述分镜，模型、采样参数与画幅固定，避免每次手工调参。

## Mechanism

```text
剧本 / 分镜脚本
→ FlowForge 调度引擎
→ CDP 驱动本地 Chrome（复用登录态）
→ Google Flow 逐镜生成
→ 尾帧抽取 → 注入下一镜首帧
→ moov atom 完整性 + 体积门禁
→ MAD 连贯性质检
→ 串联成片
```

## Evidence

- GitHub 公开开源：`hongrenw111-debug/flowforge`（main 分支）。
- Ubuntu + Windows 双系统 GitHub Actions CI，全量 **209 个单元测试**回归通过；最后一次成功运行 2026-09-01。
- 实测尾帧接力模式输出 **MAD（平均绝对差）= 2.00** 的连贯视频。
- `moov atom` 探测与体积门禁实现了对损坏视频的自动剔除与重试。

## 当前边界

- 多镜头合成依赖本地环境与 FFmpeg 命令行；在线分镜可视化前端与音画对齐播放器仍在按阶段开发。
- 仓库自 2026-09-01 后未再提交，README 中的「持续保活」应读作「CI 配置已就绪」，不宜表述为持续活跃维护。
- 核心能力依存于本地真实 Chrome 上下文，不适用于无头云集群大规模并发。
