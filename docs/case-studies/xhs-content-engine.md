# Case Study 04 — 小红书内容自动化引擎

## 结论

当前完成的是**流水线就绪的内容自动化引擎**：AI 热点嗅探与选题、图文卡片生成与排版、小红书创作者中心全静默发布三环节闭环；发布与存草稿双模式，默认落草稿。真机小批量发布验证进行中，不宣称规模化发布效果。

## Constraint

- 内容运营的日常被选题、做图、排版、发布切碎，人工节奏跟不上热点。
- 完全无人值守的自动发布有误发风险：内容质量、敏感词、平台规则都可能出问题。
- 发布动作涉及真实账号，任何自动化都必须可回退、可暂停。

## Decision

- **发布是显式动作**：`publishToXhs` 的 `action` 参数缺省为 `draft`；只有显式指定 publish 才点击发布按钮，默认仅填写表单由平台自动存云端草稿，等待人工确认。
- **静默后台**：无头持久化上下文复用登录态，不切屏、不抢焦点；键盘级输入节奏模拟真人操作。
- **提交可确认**：发布后等待服务器响应与页面跳转，异常与未登录态都会显式返回而非静默失败。

## Mechanism

```text
全网 AI 热点嗅探
→ 智能选题中台
→ 图文生成（3:4 超清卡片批量渲染）
→ 创作者中心自动化（上传 / 标题 / 正文 / 话题）
→ 草稿（默认）或 显式发布
```

## Evidence

- 发布动作必须显式指定，默认落草稿——该护栏经 2026-09-14 回归修复后确认（修复前工作区一度存在绕过 draft 分支的无条件发布改动，已恢复并提交 48b2389）。
- git 历史含三次迭代提交：图文生成流水线、创作者中心多图上传闭环、热点选品中台。
- 发布流程覆盖图片上传等待、话题联想下拉处理与提交后响应等待。
