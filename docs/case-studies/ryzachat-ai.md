# Case Study 08 — RyzaChat:AI 本地 AI 角色互动游戏

## 结论

当前完成的是**本地运行的实时角色互动原型**：主客户端整合 OpenAI 兼容模型、TTS、Spine 4.2 WebGL 动画、多会话存档与场景系统；独立 Puppet 客户端用本地面部追踪驱动角色，可作为 OBS 浏览器源。**尚未修复已知的安全与并发缺陷，仓库不公开。**

## Constraint

- 角色互动体验不是把聊天接口接到立绘上：模型回复、语音播放、口型、表情、动作、场景与环境音必须在资源受限的本地设备上保持同步。
- 多音频竞争：TTS 语音、环境音、动作音效会互相打断，需要交叉淡化与闪避策略。
- 本地运行意味着显存与内存都是硬约束，场景纹理不能一次性全加载。
- 项目使用本地商业游戏资产，**不可公开分发**。

## Decision

- **模块拆分**：对话状态、Provider 配置、语音总线、Spine 动作轨道与场景系统各自独立，避免互相耦合导致的时序问题。
- **纹理懒加载**：场景按需加载，8 个实景场景 × 4 个时段变体 + 2 张插画场景，共 34 个可切换场景。
- **环境音昼夜切换 + 语音闪避**：说话时压低环境音，不说话时恢复，避免人声被淹没。
- **面捕独立成客户端**：MediaPipe 面捕拆为独立 Web 客户端，把头部姿态、眨眼、口型与表情映射到骨骼，与游戏主进程隔离，互不阻塞。

## Mechanism

```text
玩家输入
→ LLM Provider（OpenAI 兼容 / 本地模型）
→ 对话状态与角色卡
→ 语音总线（TTS + 环境音闪避）
→ Spine 4.2 动作轨道（多轨动作 / 表情 / 眨眼 / 实时口型）
→ 场景系统（纹理懒加载 / 昼夜变体）
```

## Evidence

- 当前代码在主客户端识别 63 个函数，覆盖场景、会话、语音、环境音、Provider 配置与姿态切换。
- 源码定义 8 个实景场景的四时段变体，并追加 2 张无时段插画场景，共 **34 个可切换场景**。
- 本地资产清单含 **74 条环境音**；场景代码按需加载纹理，音频代码包含交叉淡化与语音闪避。
- 独立 Puppet Web 客户端存在本地面捕启停、平滑、镜像与头部姿态映射入口，驱动 **298 根骨骼**。

## 当前边界（必须如实标注）

- **未修复项**：Provider URL 拼接、输出转义、密钥存储方式与音频并发。公开前必须处理。
- **素材不可分发**：使用本地商业游戏资产，公开仓库与演示包必须替换为可分发占位素材。
- **未经复测**：不宣称稳定帧率或商业发行能力。
- 当前状态为**本地原型**，不是可交付产品。

## 这个案例在作品集里的定位

它展示的是**实时多媒体系统的整合能力**——模型、语音、动画、面捕四条异步链路在本地同步。但它同时也是一份诚实的反面样本：项目有已知缺陷且未修完。放在作品集里，价值在于「我清楚它现在缺什么」，而不是「它已经完成」。
